# Diagnostics playbook

## Principles

1. Prefer **read-only** Actions: `/kpax health`, `/kpax diag`, `/kpax e2e`, `/kpax analytics`.
2. SoftProbe HTTP **204/200 + egress IP** = path works. TCP open alone is **not** Connected.
3. Separate **TOOL** failures (missing `ci-e2e.env`, wrapper missing) from **VPN** failures.
4. Do **not** change PL exit config until SoftProbe RCA is written and operator confirms.

## Order for an outage

1. `/kpax health` — which hosts fail TCP/HTTP.
2. `/kpax diag panel,de,fi,pl,ru,ru2` — services, disk, journals, certs, firewall.
3. `/kpax e2e` — Reality SoftProbe fronts 2443/2444/2445 + directs; STATUS fails if PL SoftProbe fails.
4. Read Actions log stream (`SUMMARY`, `NODE …=`, `CLASS=TOOL|VPN`, `HINT HTTP_000`).
5. Fail logs on panel: `/var/log/k-pax-ci/e2e/fail-*.log` (redacted; also mirrored in e2e job output).
6. If mutate needed: `/kpax backup` → approve → change → `/kpax health` + `/kpax e2e` → `/kpax rollback` if bad.

## Layer checks (what E2E reports)

| Layer | Signal |
|-------|--------|
| TCP | `tcp … open` / `FAIL_TCP` |
| SoftProbe HTTP | `SoftProbe HTTP 204 OK` / `HTTP 000` |
| Egress IP | `egress=<ip>` vs `E2E_EXPECT_*` |
| Keys present | `SKIP_NO_KEYS` (no borrowing front PBK/SID) |
| Tooling | `CLASS=TOOL` |

## Dedicated test account

- `public_id=CI-E2E` in panel DB (long-lived).
- Env file `/etc/k-pax/ci-e2e.env` generated by `kpax-ci ensure-e2e-env` from panel `config.json` (individual node PBK/SID; empty ⇒ skip that direct path).
- Never use a random paying customer UUID.
- After ensure: sync UUID onto nodes (`sync-users` / panel maintenance) if SoftProbe auth fails for all exits.
